Again.</p>
<p>Each time a new LLM model comes out, that's the same story.</p>
<p>LLMs have limitations so we build scaffolding around them. Each models introduce new capabilities so that old scaffoldings must be deleted and new ones be added.</p>
<p>But as we move closer to super intelligence, less scaffoldings are needed. This post is about what it takes to build successfully in AI today.</p>
<h2 id="why-we-build-scaffolding"><a class="heading-anchor" href="#why-we-build-scaffolding">Why We Build Scaffolding?</a></h2>
<p>Every line of scaffolding is a confession: the model wasn't good enough.</p>
<ul>
<li>LLMs can't read PDF? Let's build a complex system to convert PDF to markdown</li>
<li>LLMs can't do math? Let's build compute engine to return accurate numbers</li>
<li>LLMs can't handle structured output? Let's build complex JSON validators and regex parsers</li>
<li>LLMs can't read images? Let's use a specialized image to text model to describe the image to the LLM</li>
<li>LLMs can't read more than 3 pages? Let's build a complex retrieval pipeline with a search engine to feed the best content to the LLM.</li>
<li>LLMs can't reason? Let's build chain-of-thought logic with forced step-by-step breakdowns, verification loops, and self-consistency checks.</li>
</ul>
<p>etc, etc... millions of lines of code to add external capabilities to the model.</p>
<p>But look at models today: GPT-5 is solving frontier mathematics, Grok-4 Fast can read 3000+ pages with its 2M context window, Claude 4.5 sonnet can ingest images or PDFs, all models have native reasoning capabilities and support structured outputs.</p>
<p>The once essential scaffolding are now obsolete. Those tools are backed in the model capabilities.</p>
<h2 id="why-its-so-hard-to-build-in-ai"><a class="heading-anchor" href="#why-its-so-hard-to-build-in-ai">Why it's so hard to build in AI?</a></h2>
<p>It's nearly impossible to predict what scaffolding will become obsolete and when. What appears to be essential infrastructure and industry best practice today can transform into legacy technical debt within months.</p>
<p>The best way to grasp how fast LLMs are eating scaffolding is to look at their system prompt (the top-level instruction that tells the AI how to behave).</p>
<p>Looking at the prompt used in Codex, OpenAI coding agent from GPT-o3 model to GPT-5 is mind-blowing.</p>
<p><strong>GPT-o3 prompt: 310 lines</strong></p>
<p><strong>GPT-5 prompt: 104 lines</strong></p>
<p>The new prompt removed 206 lines. A 66% reduction.</p>
<p>GPT-5 needs way less handholding. The old prompt had complex instructions on how to behave as a coding agent (personality, preambles, when to plan, how to validate). The new prompt assumes GPT-5 already knows this and only specifies the Codex-specific technical requirements (sandboxing, tool usage, output formatting).</p>
<p>The new prompt removed all the detailed guidance about autonomously resolving queries, coding guidelines, git usage. It's also less prescriptive. Instead of "do this and this" it says "here are the tools at your disposal."</p>
<p>As we move closer to super intelligence, the models require more freedom and leeway (scary, lol!).</p>
<p>Advanced models require simple instructions and tooling. Claude Code, the most sophisticated agent today, relies on a simple filesystem instead of a complex index and use bash commands (find, read, grep, glob) instead of complex tools.</p>
<p>It moves so fast. Each model introduces a new paradigm shift. If you miss a paradigm shift, you're dead.</p>
<p>Having an edge in building AI applications require deep technical understanding, insatiable curiosity, and low ego. By the way, because everything changes, it's good to focus on what won't change</p>
<h2 id="the-four-llm-constants"><a class="heading-anchor" href="#the-four-llm-constants">The Four LLM Constants</a></h2>
<h3 id="context-windows-the-great-expansion"><a class="heading-anchor" href="#context-windows-the-great-expansion">Context Windows: The Great Expansion</a></h3>
<p>Context window is how much text you can feed the model in a single conversation. Early model could only handle a couple of pages. Now it's thousands of pages and it's growing fast.</p>
<p>Dario Amodei the founder of Anthropic expects 100M+ context windows while Sam Altman hinted at billions of context tokens. It means the LLMs can see more context so you need less scaffolding like retrieval augmented generation.</p>
<ul>
<li>November 2022: GPT-3.5 could handle 4K context</li>
<li>November 2023: GPT-4 Turbo with 128K context</li>
<li>June 2024: Claude 3.5 Sonnet with 200K context</li>
<li>June 2025: Gemini 2.5 Pro with 1M context</li>
<li>September 2025: Grok-4 Fast with 2M context</li>
</ul>
<h3 id="generation-speed-from-seconds-to-instant"><a class="heading-anchor" href="#generation-speed-from-seconds-to-instant">Generation Speed: From Seconds to Instant</a></h3>
<p>Models used to stream at 30-40 tokens per second. Today's fastest models like Gemini 2.5 Flash and Grok-4 Fast hit 200+ tokens per second. A 5x improvement.</p>
<p>On specialized AI chips (LPUs), providers like Cerebras push open-source models to 2,000 tokens per second.</p>
<p>We're approaching real-time LLM: full responses on complex task in under a second.</p>
<h3 id="intelligence-there-is-no-wall"><a class="heading-anchor" href="#intelligence-there-is-no-wall">Intelligence: There is no Wall</a></h3>
<p>LLMs are becoming exponentially smarter. With every new model, benchmarks get saturated. On the path to AGI, every benchmark will get saturated. Every job can be done and will be done by AI.</p>
<p>As with humans, a key factor in intelligence is the ability to use tools to accomplish an objective. That is the current frontier: how well a model can use tools such as reading, writing, and searching to accomplish a task over a long period of time.</p>
<p>This is important to grasp. Models will not improve their language translation skills (they are already at 100%), but they will improve how they chain translation tasks over time to accomplish a goal. For example, you can say, "Translate this blog post into every language on Earth," and the model will work for a couple of hours on its own to make it happen.</p>
<p>Tool use and long-horizon tasks are the new frontier.</p>
<h3 id="cost-the-cost-of-intelligence-is-going-to-zero"><a class="heading-anchor" href="#cost-the-cost-of-intelligence-is-going-to-zero">Cost: The Cost of Intelligence is Going to Zero</a></h3>
<p>The cost of intelligence is going to zero. As Sam Altman noted:</p>
<blockquote>
<p>"The cost to use a given level of AI falls about 10× every 12 months, and lower prices lead to much more use."</p>
</blockquote>
<p>Today's smartest model costs what the smartest model cost 3 years ago. This exponential decline in pricing means AI capabilities that were once prohibitively expensive are becoming accessible to everyone.</p>
<h2 id="what-nobody-tells-you-about-scaffolding"><a class="heading-anchor" href="#what-nobody-tells-you-about-scaffolding">What Nobody Tells You About Scaffolding</a></h2>
<p>The uncomfortable truth: most engineers are maintaining infrastructure that shouldn't exist.</p>
<p>Models will make it obsolete and the survival of AI apps depends on how fast you can adapt to the new paradigm. That's what startups have an edge over big companies. Bigcorp are late by at least two paradigms.</p>
<p>Some examples of scaffolding that are on the decline:</p>
<ul>
<li><strong>Vector databases</strong>: Companies paying thousands/month for when they could now just put docs in the prompt or use agentic-search instead of RAG (my article on the topic)</li>
<li><strong>LLM frameworks</strong>: These frameworks solved real problems in 2023. In 2025? They're abstraction layers that slow you down. The best practice is now to use the model API directly.</li>
<li><strong>Prompt engineering teams</strong>: Companies hiring "prompt engineers" to craft perfect prompts when now current models just need clear instructions with open tools</li>
<li><strong>Model fine-tuning</strong>: Teams spending months fine-tuning models only for the next generation of out of the box models to outperform their fine-tune (cf my 2024 article on that)</li>
<li><strong>Custom caching layers</strong>: Building Redis-backed semantic caches that add latency and complexity when prompt caching is built into the API.</li>
</ul>
<p>This cycle accelerates with every model release. The best AI teams master have critical skills:</p>
<ul>
<li><strong>Deep model awareness</strong>: They understand exactly what today's models can and cannot do, building only the minimal scaffolding needed to bridge capability gaps.</li>
<li><strong>Strategic foresight</strong>: They distinguish between infrastructure that solves today's problems versus infrastructure that will survive the next model generation.</li>
<li><strong>Frontier vigilance</strong>: They treat model releases like breaking news. Missing a single capability announcement from OpenAI, Anthropic, or Google can render months of work obsolete.</li>
<li><strong>Ruthless iteration</strong>: They celebrate deleting code. When a new model makes their infrastructure redundant, they pivot in days, not months.</li>
</ul>
<p>It's not easy. Teams are fighting powerful forces:</p>
<ul>
<li><strong>Lack of awareness</strong>: Teams don't realize models have improved enough to eliminate scaffolding (this is massive btw)</li>
<li><strong>Sunk cost fallacy</strong>: "We spent 3 years building this RAG pipeline!"</li>
<li><strong>Fear of regression</strong>: "What if the new approach is simple but doesn't work as well on certain edge cases?"</li>
<li><strong>Organizational inertia</strong>: Getting approval to delete infrastructure is harder than building it</li>
<li><strong>Resume-driven development</strong>: "RAG pipeline with vector DB and reranking" looks better on a resume than "put files in prompt"</li>
</ul>
<p>In AI the best team builds for fast obsolescence and stay at the edge.</p>
<h2 id="the-counter-intuitive-truth"><a class="heading-anchor" href="#the-counter-intuitive-truth">The counter intuitive truth</a></h2>
<p>Software engineering sits on top of a complex stack. More layers, more abstractions, more frameworks. Complexity was a sophistication. A simple web form in 2024? React for UI, Redux for state, TypeScript for types, Webpack for bundling, Jest for testing, ESLint for linting, Prettier for formatting, Docker for deployment….</p>
<p>AI is inverting this. The best AI code is simple and close to the model.</p>
<p>Experienced engineers look at modern AI codebases and think: "This can't be right. Where's the architecture? Where's the abstraction? Where's the framework?"</p>
<p>The answer: The model ate it bro, get over it. The worst AI codebases are the ones that were best practices 12 months ago.</p>
<p>As models improve, the scaffolding becomes technical debt. The sophisticated architecture becomes the liability. The framework becomes the bottleneck.</p>
<p><strong>LLMs eat scaffolding for breakfast and the trend is accelerating.</strong></p>
